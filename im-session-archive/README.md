# im-session-archive

两件事：**归档 IM 通道的旧会话** + **维护跨会话的长期上下文**（`LONGTERM.md`）。

## ① 归档（原有能力）

新开一个 IM 通道会话时，把**同一个通道**的旧会话归档：

- 只往 `workspace.json` 的 `global.archivedSessionIds` 加 id —— **只归档，绝不删除**
- 按「通道前缀」分组：微信只归档微信、QQ 只归档 QQ，**绝不按工作区清**
- 保留最近 `keep` 个（默认 **1**），**永远不动当前会话**
- `dryRun` 默认 **true**：第一步只写日志，确认规则对了再改 false

## ② 长期上下文交接（2026-11-09 改版）

不再给「最后一段会话」写一次性快照，而是维护一份**跨会话累积**的长期上下文：

- **长期状态**（模型 / 人维护）—— 插件只原样搬运，**永不覆盖**
- **会话时间线**（插件维护）—— 每段会话一条，最新在上，超过 `maxSessions` 滚动丢弃

写入时机：

- 新 IM 会话出现 → 把即将退场的旧会话事实并进去（新会话开局就能读到）
- 每个 `turn/end` → 把当前会话最新一轮并进去（「一直在更新」）

单一事实源：`longterm-state.json`；渲染成 `LONGTERM.md`，并镜像一份 `AUTO-latest.md`。
模型对 `LONGTERM.md` 里「长期状态」区的编辑，会在下次渲染前被读回 state，不会被覆盖（marker：`<!-- longterm:notes:begin/end -->`）。

## 工具：`longterm_search`

在 `LONGTERM.md` 里按关键词检索相关片段（**只读、免费、不联网**）。

- 参数：`query`（必填，空格分隔多个；中文会自动切二字词）、`limit`（默认 6，最多 20）
- 返回：命中段落数 + 前 N 段（带 `L<起始行>-<结束行>` 与得分，正文截 260 字）
- 场景：文件已经 100KB+，**全量读太贵**，按需召回几片更划算

> 2026-11-16 加。注意：它只是**加一个检索入口**，不改变「每轮注入」的既有行为。

## 铁律（别改）

1. 只归档、绝不删除
2. 绝不按工作区清，只按通道前缀分组
3. 保留最近 `keep` 个，永远不动当前会话
4. `dryRun` 默认 true
5. 交接文档是**机械摘要**：只读 projcache，不调模型、不花 token
6. 长期状态区（notes）插件永不覆盖

## 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `channels` | — | 参与管理的通道名（同样是「通道名 + 分隔符」前缀匹配） |
| `keep` | `1` | 每个通道保留最近几个未归档会话 |
| `maxSessions` | 内置 | 时间线最多保留多少段会话 |
| `dryRun` | `true` | 只写日志、不真的归档 |
