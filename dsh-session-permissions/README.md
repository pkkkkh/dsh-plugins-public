# dsh-session-permissions

让**「IM 通道会话」**和**「指定工作区」**自动拿到完全文件权限，其它会话完全不受影响。

> **安全默认**：装好后 `channels` 与 `workspaces` 都是空的 → **插件完全不介入**，不会给任何会话放权。
> 要用，就把你自己信任的通道名或工作区目录写进一层 `cordis.patch.yml` 覆盖（详见下文「配置」）。

## 为什么需要它

DSH 的权限原本是**部署级开关**（`DSH_PERMISSION_MODE`）——一开就是所有会话全权限，
桌面会话、别人的会话也一起放开。而权限模式其实是**每个会话独立的投影**，
由三条事件决定：`permission/preset` → `sandbox/mode` → `approval/policy`。

本插件只给「该给的会话」补这三条，别的一律不碰。

## 判定（任一命中即开）

1. **会话标题前缀 = 某个 IM 通道名**（如「微信 · 对话4」「QQ-闲聊」）
   - 通道名后面**必须**跟分隔符（空格 / `·` / `:` / `-` / `｜` / `/` 等），
     避免「微信小程序开发」这种桌面会话被误判成微信通道
2. **会话的 cwd 落在白名单目录里**（与来源无关）

触发时机：标题是 `session/title` 事件、可能晚于创建写入，所以监听会话事件流；
工作区规则不需要标题，另在首条用户消息时补一次。

## 配置

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `channels` | `[]` | IM 通道名列表（标题前缀匹配） |
| `workspaces` | `[]` | 白名单目录（cwd 落在其中即命中） |
| `mode` | `danger-full-access` | 下发给会话的 sandbox 模式（**只在命中 `channels`/`workspaces` 时才下发**） |
| `preset` | 同 `mode` | `permission/preset` 的内容 |
| `approval` | `never` | `never` / `ask`；传 `null` 或 `""` 表示不动审批策略 |
| `recursive` | `true` | 白名单是否包含子目录 |

## 注意

- `channels` 和 `workspaces` **都为空时插件完全不介入**（等同于没装）
- 同一会话只追加一次（`WeakSet` 去重），不会每轮重复写
